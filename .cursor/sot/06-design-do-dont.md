# UI/UX Do & Don't 원칙
> 업계 표준 + 개인 취향 반영본. ★ 표시는 개인 스타일 기준.
> 커서는 이 원칙을 기본으로 적용한다. 클라이언트가 명시적으로 요청할 때만 예외를 허용한다.

---

## 1. 레이아웃 & 여백

| ✅ DO | ❌ DON'T |
|-------|---------|
| 섹션 간격 > 요소 간격 > 내부 간격 순서 유지 | 콘텐츠가 컨테이너 끝까지 꽉 차게 |
| 여백을 디자인 요소로 전략적으로 사용 | 여백을 남은 공간 처리로 |
| 관련 요소끼리 가깝게, 무관한 요소끼리 멀게 | 관련 없는 요소 간격이 관련 있는 것보다 좁게 |
| CTA 주변에 여백 충분히 줘서 시선 유도 | 요소를 너무 빽빽하게 배치 |
| 12컬럼 그리드 기반으로 정렬 | 정렬 없이 눈대중으로 배치 |
| 모르면 여백을 더 줘라 | 여백이 아깝다고 채우기 |

---

## 2. 색상 & 대비

| ✅ DO | ❌ DON'T |
|-------|---------|
| 텍스트-배경 대비 최소 4.5:1 (WCAG AA) | 연한 배경에 연한 텍스트 |
| 60-30-10 비율 (배경:보조:강조) | 포인트 색상 3개 이상 동시에 |
| 채도 높은 색 한 페이지에 1~2개만 | 채도 높은 배경 + 채도 높은 텍스트 |
| 섹션 전환은 여백·타이포·배경·이미지 중 적절한 방법으로 구분 | 구분 수단 없이 섹션이 붙어 보임 |
| 본문 텍스트: #1A1A1A~#333 | 순수 #000000 텍스트 |
| 어두운 배경 위 텍스트는 #F5F5F5 크림색 | 순수 #FFFFFF로만 처리 |
| 그림자 기본은 중립색 alpha · 토큰 스케일 사용 | 순수 `#000` 불투명 그림자 · 값 매번 임의 |

---

## 3. 타이포그래피

| ✅ DO | ❌ DON'T |
|-------|---------|
| 위계 차이는 명확하게 (최소 1.5배 크기 차이) | 애매한 크기 차이 (2px 차이 등) |
| 본문 줄간격 1.5~1.7 유지 | 줄간격 없이 빡빡하게 |
| 한 페이지 폰트 굵기 2~3가지만 | 강조한다고 전부 Bold |
| 제목, 짧은 카피에만 가운데 정렬 | 본문 텍스트 가운데 정렬 |
| 본문 줄 길이 45~75자 유지 | 가로로 너무 길게 뻗은 텍스트 |
| 타이포가 디자인 성격을 전달하게 | 폰트를 중립적 전달 도구로만 |

---

## 4. 버튼 ★ 개인 취향 강하게 반영

| ✅ DO | ❌ DON'T |
|-------|---------|
| Primary 버튼은 한 화면에 1개 원칙 | Primary 버튼 여러 개 나열 |
| Secondary는 Primary와 나란히 있을 때만 아웃라인 허용 | 단독 버튼에 아웃라인 사용 ★ |
| 버튼 문구는 동사로 시작 (시작하기, 신청하기) | 명사형 문구 (확인, 제출, 완료) |
| 버튼 라운드는 브랜드 성격과 일치 | 이유 없는 pill 버튼 남발 |
| 비활성 버튼 opacity 40% | 비활성인데 색상만 바꿔서 구분 |
| 로딩 중 버튼 비활성화 필수 | 클릭 후 중복 요청 방치 |
| 아이콘 위치: 방향성(→)만 오른쪽, 나머지 왼쪽 | 아이콘 위치 일관성 없이 |

---

## 5. 카드 ★ 개인 취향 강하게 반영

| ✅ DO | ❌ DON'T |
|-------|---------|
| 카드 구분은 그림자 또는 배경색으로 | 카드에 테두리(border) 사용 ★ |
| 카드 안 이미지 비율 전체 통일 (16:9 또는 4:3) | 이미지 비율 제각각 |
| 카드 안이 답답하지 않게 · PC 기본 padding **24px** · 카드 간 gap **24px** | 카드 내부가 답답하게 꽉 참 |
| 호버 시 그림자는 아래로만 (translateY + shadow) | 그림자가 위로 올라오는 호버 |
| 카드 안 정보 3가지 이내로 | 카드 안에 정보 과부하 |
| 3개 또는 6개 배치가 가장 안정적 | 5개, 7개 등 불규칙한 카드 수 |
| 카드 높이 균일하게 (flex stretch) | 카드마다 높이 제각각 |

---

## 6. 이미지

| ✅ DO | ❌ DON'T |
|-------|---------|
| 고해상도, 고품질 이미지 사용 | 저해상도 이미지 원본 그대로 |
| object-fit: cover로 비율 고정 | 이미지 스트레칭 |
| 이미지 위 텍스트는 반드시 오버레이 처리 | 오버레이 없이 이미지 위에 텍스트 ★ |
| WebP 포맷 우선 사용 | PNG/JPG 원본 그대로 |
| Lazy load 필수 | 모든 이미지 한번에 로드 |
| 모든 이미지 alt 텍스트 | alt 없이 납품 |
| 사람 사진의 시선 방향으로 CTA 배치 | 시선이 CTA 반대 방향으로 |
| 관련성 있는 이미지 | 분위기만 맞는 스톡 이미지 남발 |

---

## 7. 보더 & 그림자 ★

| ✅ DO | ❌ DON'T |
|-------|---------|
| 그림자로 요소 부각 (기본=중립 alpha) | 카드, 버튼, 인풋 전부 보더로 처리 ★ |
| 그림자는 빛이 위에서 오는 방향 (아래로) | 그림자가 위로 올라가는 방향 |
| 그림자 opacity 미묘하게 (0.06~0.16) | 과한 불투명 그림자 |
| 컬러 그림자는 CTA·브랜드 포인트 등 제한적 | 모든 그림자를 컬러로 통일 강제 |
| 보더는 인풋, 테이블, 구분이 꼭 필요한 곳만 | 여기저기 보더 남발 ★ |
| Secondary 버튼 아웃라인은 Primary와 나란할 때만 | 단독 아웃라인 버튼 ★ |
| 그림자 토큰(sm/md/lg…) 일관 적용 | 그림자 값 매번 임의로 |

---

## 8. 아이콘

| ✅ DO | ❌ DON'T |
|-------|---------|
| 한 프로젝트에 아이콘 패밀리 하나만 | 라인 아이콘 + 필드 아이콘 혼용 ★ |
| 아이콘 크기: 텍스트 크기와 맞춤 | 텍스트 대비 너무 크거나 작은 아이콘 |
| 범용 아이콘 관행 따르기 (돋보기=검색, 집=홈) | 독창성을 위해 낯선 아이콘 |
| 아이콘 + 텍스트 함께 (초기엔) | 아이콘만 단독으로 의미 전달 |

---

## 9. 네비게이션

| ✅ DO | ❌ DON'T |
|-------|---------|
| 메뉴는 과업·우선순위로 구성 · **6개 이상이면 그룹핑 검토** | 메뉴를 이유 없이 끝없이 나열 |
| 현재 페이지는 굵기 변화로 표시 | 색상만으로 현재 위치 표시 |
| 스크롤 시 헤더 blur() + 반투명 | 스크롤 시 헤더 그냥 사라짐 |
| 브레드크럼은 계층이 깊거나 상위 이동이 필요할 때만 | 1단 사이트에 브레드를 장식으로 넣기 |
| 모바일 햄버거: 오른쪽 슬라이드인 | 위에서 덮어씌우는 방식 |

---

## 10. 폼

| ✅ DO | ❌ DON'T |
|-------|---------|
| 라벨은 항상 인풋 위에 | placeholder만으로 라벨 대체 |
| 오류: 색상 + 아이콘 + 텍스트 함께 | 색상만으로 오류 표시 |
| 필수 대신 선택 항목에 "(선택)" 표기 | 모든 필드에 * 표시 |
| 폼 필드 최소화 | 불필요한 필드 추가 |
| 제출 버튼 폼 마지막 필드 바로 아래 | 버튼이 폼과 멀리 떨어짐 |
| 로딩 중 제출 버튼 비활성화 | 중복 제출 방치 |

---

## 11. 모션 & 인터랙션

| ✅ DO | ❌ DON'T |
|-------|---------|
| 모션은 시선 유도 목적일 때만 | 목적 없는 장식용 모션 |
| duration 0.3~0.6s (스크롤 애니메이션) | duration 1초 이상 |
| 한 섹션에 모션 1~2개 | 한 섹션에 모션 3개 이상 |
| 모바일에서 틸트, 패럴랙스 비활성화 | 모바일에서도 무거운 모션 |
| hover 효과는 데스크탑에만 | 모바일에서 hover 효과 |
| 모션 후 원래 자리로 부드럽게 복귀 | 모션이 레이아웃을 건드림 |

## 12. UX 컨벤션 (관행 따르기)

| ✅ DO | ❌ DON'T |
|-------|---------|
| 히어로 3초 안에 "뭐하는 곳인지" 읽히게 | 히어로를 감성으로만 채우기 |
| 신뢰 요소를 CTA 바로 위/아래에 배치 | 신뢰 요소를 하단에 묻어두기 |
| 밑줄 있는 링크 텍스트 | 밑줄 없는 파란색 텍스트 (링크 오해) |
| 로딩 상태 항상 표시 | 클릭 후 반응 없이 기다리게 |
| 빈 상태(empty state)에 안내 + 다음 행동 | "데이터가 없습니다" 텍스트만 |
| 관행적인 아이콘 의미 그대로 사용 | 독창성을 위해 낯선 UX 패턴 |
| 반응형: PC·모바일을 **함께 설계** · CSS는 **모바일 퍼스트** | 한쪽만 보고 납품 직전 대응 |

---

## 13. 이미지 & 접근성

| ✅ DO | ❌ DON'T |
|-------|---------|
| 포커스 상태 스타일 명시 (outline 커스텀) | outline: none 처리 후 끝 |
| 터치 타겟 최소 44x44px | 작은 버튼/링크 모바일에서 |
| 모바일 텍스트 최소 16px | 14px 이하 본문 |
| 모바일 좌우 여백 최소 16px | 모바일 여백 없이 꽉 차게 |

## 14. 개인 스타일 요약 ★

```
카드     → 보더 없이. 그림자 또는 배경색으로 구분
           PC 기본 padding 24 / gap 24 · 내외부 대소 강제 없음
버튼     → Primary 단독일 때 아웃라인 금지
           Secondary는 Primary와 나란히 있을 때만 아웃라인
보더     → 인풋, 테이블, 꼭 필요한 곳에만
그림자   → 기본=중립 alpha · 컬러는 제한적
아이콘   → 한 패밀리만, 라인/필드 혼용 금지
이미지   → 오버레이 없이 텍스트 절대 금지
메뉴     → 개수 하드캡 없음 · 6+면 그룹핑 검토
브레드   → 깊을 때만 (필수 아님)
섹션구분 → 배경색 강제 아님 · 여백·타이포·배경·이미지 선택
```

## 커서 적용 기준

```
이 원칙에 어긋나는 구현을 요청받으면:
1. 일반 ❌ DON'T → 대안을 함께 제안하고 진행
2. ★ 개인 스타일 DON'T → 명시적으로 알리고 확인 후 진행
3. 접근성 관련 → 반드시 경고 후 진행 여부 확인
```
